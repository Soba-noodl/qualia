# Danger Zones

## vercel.json — Strict Schema, No Comments

Vercel validates `vercel.json` against a strict schema and rejects unknown
properties (including comment-style keys like `_comment_*`). If you need
to explain a config decision, put the explanation here or in the commit
message — never as an `_comment` key.

Production gotcha discovered 2026-05-24: a `_comment_rewrites` key added
in commit `4423f5e` silently broke every deploy for 17 hours. Vercel
errored with "should NOT have additional property `_comment_rewrites`"
but no monitoring alerted because deploys-failing is not a tracked
condition.

The current rewrites hardcode the Supabase project ID `zujbauyrpisjdqmjhmgr`
in the `/mcp` and `/mcp-auth` destinations. That's intentional: Vercel
rewrites don't support env-var interpolation, the project ID is already
public via the anon key shipped in the web bundle, and the single-project
deployment topology doesn't need per-environment routing. Don't try to
parametrize without splitting the config.

## Data Layer Bypass — Forbidden

Never call Supabase in a component:

```tsx
// ✗ bypasses caching and makes RLS enforcement invisible
const { data } = await supabase.from('audits').select('*')

// ✓ always through the service → hook chain
const { data } = useAudits()
```

## Figma Plugin Runtime Confusion

The plugin has two runtimes that cannot share runtime state:
- **Sandbox** (`code.ts`): has `figma.*`, no `window`, no external `fetch`
- **UI** (`src/ui/`): has DOM and `fetch`, no `figma.*`

Importing sandbox utilities in the UI (or vice versa) fails silently in Figma.

## Destructive DB Operations

`DROP`, `TRUNCATE`, bulk `DELETE` require explicit user approval. Propose a migration with a rollback plan first.

## New `public` Tables Need Explicit Grants

From **2026-10-30**, Supabase no longer auto-grants `public` tables to `anon` / `authenticated` / `service_role`. A `create table public.x` migration without an accompanying `grant ... on public.x to ...` will compile fine but cause runtime `42501 permission denied` from `supabase-js`/PostgREST. Existing tables (created before 2026-05-14) keep their grandfathered grants — verified via `information_schema.role_table_grants` on both `zujbauyrpisjdqmjhmgr` (Qualia) and `qabrznbuzfelzzpyfaod` (all-vitals). Use the migration template in `conventions.md` §13 for every new table. `SEC-006` enforces this.

## Secrets

`.env` is gitignored. `SUPABASE_SERVICE_ROLE_KEY` and `DATABASE_URL` must never be committed. `VITE_*` vars are intentionally public (bundled into the browser) — never put secrets in them.

## Shared Module Drift

Never duplicate logic from `supabase/functions/_shared/` into individual functions. The Gemini model name in `analyze-run.ts` has changed before — hardcoded copies go stale.

## Supabase OAuth Redirect URL Whitelist

Supabase Dashboard → Authentication → URL Configuration must be kept in sync whenever new deployment domains are added. If a redirect URL is missing, Google OAuth silently fails — the callback returns with no session and no visible error to the user.

**Current approved list (as of 2026-05-05):**

| URL | Purpose |
|---|---|
| `https://qualia-ux.com` | Site URL (production) |
| `https://qualia-ux.com/dashboard` | Post-login landing |
| `https://qualia-ux.com/auth` | OAuth return target |
| `https://qualia-ux.com/auth?**` | OAuth return with query params (e.g. `?returnTo=`) |
| `https://qualia-ux.com/plugin-auth` | Plugin OAuth return |
| `https://qualia-ux.com/plugin-auth?**` | Plugin OAuth with `?figma_state=` |
| `http://localhost:8080/**` | Local development |

**Do not add** `https://*.vercel.app/**` — too broad; any Vercel project could be used as a redirect target. Add specific preview URLs explicitly and remove them after the deployment is retired.

## ESLint Baseline (Non-Zero Exit Is Normal)

The repo carries **~23 pre-existing ESLint errors** (mostly `@typescript-eslint/no-explicit-any` in UI code and Supabase edge functions). `npm run lint` exits non-zero by default. **These are not regressions** — don't chase them as if recent edits caused them. Only act on errors introduced by the current change.

## Package Manager

Both `package-lock.json` (npm) and `bun.lockb` exist in the repo. **Always use `npm`.** Do not run `bun install` or treat the bun lockfile as canonical.

## Cron Jobs Require `app.settings.functions_base_url`

Migration `20260523192000_parametrize_cron_urls.sql` rebound the welcome-email trigger and both pg_cron jobs (`send-retention-emails-daily`, `storage-cleanup-weekly`) to read the Edge Functions base URL from a database setting instead of hardcoding the production project ID. Before this migration is applied to a fresh environment, set the value:

```sql
ALTER DATABASE postgres SET app.settings.functions_base_url
  = 'https://<project_ref>.supabase.co/functions/v1';
```

If unset, the welcome-email trigger raises an exception on every audits INSERT, and the cron jobs POST to a relative path that pg_net rejects. Both fail loudly rather than silently calling the wrong project.

## `showcase_audits` Requires `app.settings.showcase_publisher_emails`

Migration `20260523190000_showcase_audits_insert_guard.sql` installs a BEFORE INSERT trigger on `public.showcase_audits` that requires:

1. The audit's `source` to be `'app'` (rejects plugin audits).
2. The audit owner's email to appear in the comma-separated `app.settings.showcase_publisher_emails` database setting.

Before running `scripts/populate-showcase-audits.ts` on a fresh environment, set the value:

```sql
ALTER DATABASE postgres SET app.settings.showcase_publisher_emails
  = 'operator@example.com,curator@example.com';
```

If unset, every insert into `showcase_audits` will fail — including service-role inserts. The trigger fires under `SECURITY DEFINER` and there is no way to bypass it short of dropping the trigger.
