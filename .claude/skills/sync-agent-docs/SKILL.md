# sync-agent-docs

## Step 1 — Diff scan

Run:
```bash
git diff origin/staging...HEAD --name-only
```

This catches all commits on the current branch since the last staging push, not just uncommitted work.

Collect the list of changed files.

## Step 2 — Scope guard

Check if any changed files match these trigger paths:
- `supabase/migrations/`
- `supabase/functions/`
- `src/services/`
- `src/hooks/`

If none match AND the user did not explicitly invoke '/sync-agent-docs', output: "No docs affected — no trigger paths changed." and stop. If invoked explicitly, proceed to Step 3 regardless.

## Step 3 — Impact map

| Changed path | Action |
|---|---|
| `supabase/migrations/` | Regenerate `agent_docs/database_schema.md` (Tier 2) |
| `supabase/functions/` | Regenerate `agent_docs/edge-functions.md` (Tier 2) |
| `src/services/` or `src/hooks/` | Regenerate `agent_docs/data-layer.md` (Tier 2) |
| Any trigger path | Review Tier 1 docs for staleness |

## Step 4 — Generate mode (Tier 2)

For each affected Tier 2 doc, read the source files and rewrite the full doc with this header:

```
<!-- AUTO-GENERATED by sync-agent-docs. Do not edit manually. Last synced: YYYY-MM-DD -->
```

### database_schema.md
Read all files in `supabase/migrations/` chronologically (`ls -1 supabase/migrations/*.sql | sort`). For each table:
- Table name
- Columns: name | type | nullable | default | notes
- Foreign key relationships
- RLS: enabled yes/no, summary of what the policy enforces

### edge-functions.md
Read each directory in `supabase/functions/` (skip `_shared/`). For each function:
- **Purpose:** 1 sentence
- **Auth:** `plugin-token` | `supabase-jwt` | `none`
- **Key inputs:** list
- **Shared modules:** which `_shared/*.ts` files it imports

### data-layer.md
Read `src/services/` and `src/hooks/`. For each domain:
- Service: `src/services/<name>.service.ts` — what DB/function operations it wraps
- Hook: `src/hooks/use-<name>.ts` — what TanStack Query queries/mutations it exposes

## Step 5 — Review mode (Tier 1)

Read `agent_docs/architecture.md`, `agent_docs/conventions.md`, and `agent_docs/danger-zones.md` alongside the changed files.

For each doc, ask: does any documented pattern, decision, or warning no longer accurately describe the current code?

- **If yes:** produce a quoted diff showing the suggested change. Ask the user: "This section appears stale — approve this update?" Write only on confirmation.
- **If no:** state "Tier 1 docs look accurate — no changes needed."

## Step 6 — Commit

```bash
git add agent_docs/
git commit -m "docs(agent-docs): sync after <brief description of triggering change>"
```
